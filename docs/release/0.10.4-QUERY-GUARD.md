   `f816fdfa44caa4c2bc14a8a5065ac7fa36b9e4d4512c022a49098c85d770cce6`.
   No process owner was identified, and no source/destination lock was weakened.
2. The test-only `--fixture-parent` / bundle `--backup-fixture-parent` option
   lets owned tests use an explicit temporary volume. R: mapped only the new
   repository-owned `build/isolated-fixture-volume-0104` directory. All sixteen
   backup cases then passed, including existing-writer refusal, reparse/overlap,
   ACL, byte verification and original-file preservation. The full bundle also
   passed six unsupported-host runs, 21 load-context cases, 63 runtime cases,
   333 storage cases/721 operations, 31,216 policy comparisons/88 traces and
   25,733 selection comparisons/59 traces. This does not prove a real pre-launch
   or pre-activation backup can currently obtain all locks on C:.
3. Clean Windows jobs first rejected the valid SDDL `LA` alias because the old
   validator searched literally for a numeric account SID. The observed root
   DACL was `D:P(A;OICI;FA;;;SY)(A;OICI;FA;;;LA)`. The new validator parses the
   descriptor and compares actual trustee SIDs against the current token and
   SYSTEM, requires exactly two allowed full-access entries, and keeps root
   inheritance protection. Eight focused tests reject foreign/additional users,
   wrong masks, unprotected/null DACLs and invalid fixture parents. Production
   backup code, permissions and locking are byte-identical to 0.10.3.
4. Clean-runner source inputs differed only in line endings (five frozen-r4
   files; three candidate files). Exact CRLF reconstruction matches the local
   recorded source digests; generated headers match. Initial ASI hashes differed
   because the JSON header's assertion diagnostics contain a UTF-16 absolute
   source path. Rebuilding at the historical source prefix reproduced **every
   product byte**, including the submitted 0.10.3 ASI and new candidate ASI.
   No stripping, renaming, scan-driven recompilation or submitted-byte change
   was used. Compiler archive/wrapper hashes remain pinned and unchanged.
