# 0.10.2-native-test multiplayer release

**Purpose:** Test whether a teleport by one player can cause an automatic
companion summon for another player who remains stationary. This is the normal
next EARLY ALPHA update, not a separate multiplayer edition.

## What this build contains

The native runtime still creates summon opportunities after a successful local
save load and ship exit. It also includes the experimental filtered teleport
callback candidate. The existing master automation switch and destination
settings remain authoritative. The request continues through the game's native
ownership, eligibility and placement checks; this change does not create pets,
reduce gameplay limits or force summons where manual summoning is unavailable.

An earlier build of the same candidate behavior produced visible pets after two
local routes: freighter-to-station and station-to-planetary-base, without a
ship exit for the second route. Opening and closing the teleporter without
selecting a destination produced no candidate event. These observations do not
establish whether the callback is successful local arrival, a transition stage
or a shared player movement event. Multiplayer and this exact archive's startup
remain unverified until tested.

Teleport behavior is experimental and can be disabled immediately with
**Automatic summoning: OFF** in the Companion Auto Summon Quick Menu page. No
death/respawn trigger is included; it remains a separate research item.

## Two-player test

1. Both players install the same archive on Windows/Steam and confirm the game
   build is the supported Cosmos 7.05 / Steam build 25624745.
2. In a location where the game's normal companion summon is available, enable
   automatic summoning and that destination on both clients. Record each
   player's selection mode and whether a pet is already active.
3. Player A stays still while Player B completes one teleport. Record whether
   A's own companion appears. Swap roles and repeat once.
4. If a remote teleport causes unexpected summoning, turn the master setting
   OFF on that client and capture only the short relevant log excerpt after
   removing personal paths and identifiers.

Report the player who teleported, the stationary player's location, each
screen's visible result, active-pet state, selection mode, and approximate
delay. Do not exchange save files or private backups. Do not infer multiplayer
behavior from a local teleport test or from an accepted queue alone; visible
appearance must be observed on each screen.
